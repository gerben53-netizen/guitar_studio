# LRCLIB Personal Lyrics Download & Import

Issue #63, one checkout on feature/lrclib-personal-lyrics-import from develop `0d1c246`. No milestone, new provider, parser, workspace model or SQL migration. The existing LRCLIB integration, v2/v1 search, 2D transaction service and 2E canonical/legacy Song contracts are retained. Final exact-head/develop CI, full browser acceptance, merge commit and issue closure are recorded in the single PR completion comment after those gates complete.

## Implementation

The selected LRCLIB preview can now proceed to text/metadata correction, explicit personal-use confirmation, existing safe destination selection and **Toevoegen aan mijn bibliotheek**. Instrumental/missing/unsafe-only records have no import action. Community-error guidance replaces the personal workflow's former absolute block. The project owner's reported contact with LRCLIB's author is attributed as supplied information; no blanket copyright licence is claimed. See [policy](../architecture/lrclib-personal-import-policy.md).

The API signs selected original preview content/album/owner/expiry with a process-private HMAC key. The existing preview/import endpoints accept the receipt with corrections; first commit verifies it and requires personalUseConfirmed, confirmed and rightsConfirmed. No client provider document or storage claim is trusted. Source/timing persist as personal-only LRCLIB provenance, with original title/artist/album, ID/URL, server import date/method, timing format and correction flags. Corrected sections remain editable separately from original raw text/timing. Workspace source details expose provenance and original synchronization. Later normal/canonical saves, duplication/export and schema conversion retain it. No automatic seconds-to-bars or lyric-to-event matching.

No DDL is needed: optional metadata fits existing JSONB and studio_imports provenance. The same transaction writes Song/history/import record. UUID/hash advisory locking prevents duplicate confirmation; replay checks precede transient receipt validation, including after an API/key restart. Stale target revision returns 409/currentRevision. Existing sections, lyrics/chords/tab and hidden v2 tracks remain intact on append/new-arrangement. Shared source-policy validation permits personal-only LRCLIB documents while still denying previews. API responses are no-store; lyric-bearing errors/payloads are omitted from logs and generic validation responses.

- 39 PostgreSQL 17 cases (32 baseline + 7): new personal content, metadata/timing/provenance, subsequent legacy/canonical writes/history, concurrent/restarted idempotency, owner isolation, no public route, safe v2 destinations/stale revision, rollback and log redaction.
- Five new installed-Chrome cases pass: full search/correction/lost-response/retry/open/edit/source/new-browser-process/destination/cancel flow and four viewports × two themes. The full regression suite contains 37 cases; final successful Chrome/CI counts are recorded in the completion comment. Failed development runs do not count as acceptance.
- Sixteen new axe scans (correction and destination at 1440×900, 1280×800, 1024×768, 390×844, dark/light) have zero violations. Screenshots contain only original test lyrics. Existing 32 browser scenarios retain all manual/ChordPro/ASCII, Workspace, multi-track compatibility, Practice/audio and design regressions.
- [Actual restart proof](../qa/evidence/lrclib-personal/restart.json): PostgreSQL restart, new API process/signing key, new Chrome process/empty context, identical document/revision/history/source/corrections/timing and successful replay with the old committed receipt. Own generated fixture removed.
- [Live LRCLIB smoke](../qa/evidence/lrclib-personal/live-smoke.json): actual v2 search, selected full record and signed personal preview all HTTP 200, no database write, no external lyrics retained in evidence. Network tests/CI use original deterministic fixtures rather than relying on provider uptime.
- [Existing local data](../qa/evidence/lrclib-personal/existing-data-preserved.json): all original 15 historical documents retain their exact digest; the current 2 Songs/17 versions differ from the previous sprint only through two lastOpened revisions. Text, music and sources are unchanged. Feature tests use a separate database; a new private pre-update dump remains ignored.

The browser fixture injects the real LRCLIB adapter at its external HTTP boundary into an isolated real Fastify/receipt/parser/PostgreSQL instance; it does not add a production backdoor. Its unique owner is removed afterward. Full suite requires a host DATABASE_URL (and, for test mode, a separate TEST_DATABASE_URL) selecting the same isolated database as the browser application. CI already provides the host database URL. Set PLAYWRIGHT_BASE_URL for a custom preview, PLAYWRIGHT_CHANNEL=chrome and PLAYWRIGHT_SCREENSHOT_DIR to an ignored directory. PERSONAL_IMPORT_EVIDENCE_DIR controls the new screenshots/scans.

Each new browser case starts its own application/provider/owner fixture so independent scenarios do not accumulate against the real 30-per-minute discovery limit. Production limits remain unchanged. Final installed-Chrome regression uses a frozen production bundle with a stable API; development hot-reload runs are not counted. Personal corrections retain invalid/correction-required parser status instead of bypassing validation, and original provider title/artist remain authoritative even if source text contains metadata-like directives.

## Remaining boundaries

Current deployment boundary is still the trusted local owner and loopback-published Compose services; this change is not new multi-user authentication. No public lyrics distribution, automatic sharing/sync, commercial publishing, new editor or CSS framework. Uncommitted receipts expire after 30 minutes or API restart and require selection again; committed request replay remains available. Original timing may no longer align after text corrections and is explicitly retained for manual review. No universal content copyright grant or transcription accuracy is asserted. No main, release tag or deployment change.
