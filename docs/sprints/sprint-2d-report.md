## Limitations / Work transfer

See [provider research and rights](../architecture/song-discovery-providers.md), [LRCLIB implementation](../architecture/lrclib-provider.md) and [import model/HTTP/persistence/track seam](../architecture/song-import-model.md). API contract details and parser support are maintained there to prevent divergent UI/backend specifications. Future Work should replace presentation while retaining source-policy status, warnings, explicit confirmation, revision/idempotency handling and separate text-column/millisecond/rational-time coordinates.

ASCII imports preserve playable fret values but do not invent exact rhythmic events from spaces; current raster is blank until manually timed. No automatic articulation/repeat/rest expansion, alternate-tuning inference, universal ChordPro implementation, online chord/tab ingestion, audio alignment or new multi-track UI. LRCLIB is externally operated and v2 beta can change. Automated responsive/axe checks are not physical-device, screen-reader or speaker certification. Trusted local owner is the existing boundary; production multi-user/multi-instance exposure requires real authentication and shared throttling. The YAML dependency is pinned and safe/strict parsing is tested.

Recommended follow-up: Work's Song Workspace v3 design against these stable contracts, with explicit human mapping of untimed note columns/lyric timestamps to musical events and separate verified provider licensing before external content storage.
