# Shared metronome engine

`packages/audio` provides React-independent MetronomeEngine and a WebAudioBackend adapter. It consumes the existing music-domain rhythmic unit conversion. One shared lazy AudioContext/graph and one 25 ms timer fill a 100 ms lookahead horizon; audioContext.currentTime is authoritative. Internal sixteenth-note indices track bar/pulse/subdivision. UI listeners receive scheduled ticks, so 2B should display ticks only when their `at` time reaches audioTime (or read position), not immediately on notification.

Simple meters use quarter-note BPM. In 6/8 BPM means dotted quarter: two main pulses per bar; eighth subdivisions are one third of a pulse and sixteenths one sixth. Accent is on the first pulse. Optional eighth/sixteenth clicks share the same clock. Gain supports volume/mute without stopping musical time; short oscillator envelopes make the clicks. No microphone or media permission is used.

Start/resume must be called from a user action. Repeated starts share one pending job/context/timer. A serialized lifecycle queue plus generation cancellation handles stop/pause/dispose during start, including a native resume promise still waiting for autoplay permission. Pause cancels queued voices, preserves the pending musical fraction and suspends the context. Resume restores that fraction; stop resets position. Dispose cancels timers/voices, closes context and releases listeners. Errors surface status=error/lastError and stop scheduling; close failure keeps the backend reference to avoid allocating a competing live context.

BPM changes rephase pending ticks at the same fraction. Meter changes deliberately stop/reset and require start. Ramp starts at its configured tempo and increases once per requested bar interval, clamped to target; rephasing near a bar does not double-increment. Tap averages up to 8 recent taps and resets after 3 seconds. A severely late timer rebases rather than emitting a burst of overdue clicks; audio timing cannot guarantee uninterrupted playback under arbitrary OS/browser suspension.

The shared adapter pauses on hidden document, stops on popstate/hashchange and disposes on pagehide. `releaseSharedMetronome()` must also be called by Sprint 2B React route/unmount owners, because pushState-based navigation does not emit popstate. `disposeSharedMetronome()` closes before clearing the singleton. Never allocate one engine per control. Current production screens are not wired to this new service in 2A.

Tests inject SchedulerClock and AudioBackend to check beat spacing, bars, BPM/tap, volume/mute, pause/resume, cancellation, ramp,6/8 and audio failures. A separate unstyled Vite test-support page exists only for browser verification; it is not a product UI or part of the production build entry. Playwright starts it via a user click with the real Web Audio API, checks a nonzero digital waveform, zero mute output, one context, suspended time and closed lifecycle. Synthetic visibility/navigation/pagehide events verify listener responses; these do not claim physical tab/audio-device or speaker listening acceptance.

References: [Web Audio specification](https://www.w3.org/TR/webaudio/) and [Chrome suspend/resume sample](https://googlechrome.github.io/samples/webaudio-suspend-resume/). No wall-clock timer is used to fire each sound directly.
