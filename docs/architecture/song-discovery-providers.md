# Song discovery providers

Research checked 2026-11-14. Technical API access and rights in the returned compositions are separate decisions. No scraping, login/paywall bypass, or arbitrary URL fetching is implemented.

`packages/shared/src/discovery.ts` defines provider identity, search capabilities, types, restrictions, results and selected detail. Results explicitly distinguish metadata, temporary preview and importable content. LRCLIB never returns `importable`. Lyrics-only provider does not fabricate chord/tab availability. A `mixed` request can return the available lyrics portion, not a mixed-content claim; chords/tab filters return no results.

Routes follow existing `/api/v1`: `GET /discovery/providers`, `GET /discovery/search`, `GET /discovery/results/:providerId/:resultId`. Strict Zod validation rejects unknown query fields, unknown providers, arbitrary URLs, unsupported pagination, oversized inputs and invalid record IDs. Search accepts `q`, `title`, `artist`, `album`, `provider`, `contentType`, `limit` (1–20). Search and detail use dependency-injected providers for reproducible tests, fixed provider endpoints for production and `Cache-Control: no-store`. No source URL becomes a fetch destination. A per-process 30 requests/minute/IP guard complements the provider's shared serial queue and server-side cooldown. This is a local-principal application, not a distributed authenticated service; a future multi-instance service needs shared quotas/authentication.

No lyrics or credentials are logged. Provider errors expose controlled messages/status/Retry-After; import/discovery validation logging omits payload/errors that might echo source. Optional credentials remain server-side. External detail cannot be submitted to `/imports`: the strict commit route accepts only user input and reparses it; caller-supplied provider documents/policy are rejected. Song create/update also rejects external/preview-only import documents. Copying material into an explicit user-content submission does not confer rights; the UI requires the user to confirm their own storage rights.
