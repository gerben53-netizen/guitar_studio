# Practice Room Home and Rhythm Lab

Sprint 2C connects the existing Practice foundation to real React screens. No demo renderer, duplicate catalog/session/progress model, music clock or metronome engine is introduced. The global shell retains Song Workspace, library, import and Song Practice Mode; its new Oefenen action opens Practice Room.

## Components and state

`PracticeRoom` loads the 18 exercises, real progress, journal and owner preferences through `createPracticeClient(request)`. Its internal navigation opens Home, Rhythm, exercise library, learning path and journal. Other Labs are visibly future modules; their 14 exercises are discoverable but have no start actions. Recommendations select the first Rhythm exercise without explicit configuration mastery; this is a simple catalog choice, not an automatic musical assessment. Resume selects the last available Rhythm selection and its current server settings. Historical session snapshots are preserved; Opnieuw oefenen loads current saved settings rather than rewriting history. Journal pagination does not replace the Home recent-session collection.

`RhythmLab` owns a validated draft, optimistic revision, capped Undo history and explicit save status. Switching exercises or leaving the app prompts before discarding a draft or unfinished session. Internal Practice navigation retains the draft/session component and pauses audio. Reload/close gets beforeunload protection. Errors provide explicit reload/retry and retain drafts; settings never silently overwrite a conflicting revision. A delayed Start save is generation-cancelled by Stop or navigation, so a late response cannot start audio on another screen.

`RhythmTimeline` renders rational whole-note starts/durations as sixteenth slots, separate from pixels. Buttons support roving focus, arrows, Home/End, selected versus playing state, stroke/rest/hold/accent text. Whole, half, quarter, eighth and sixteenth durations use the existing fraction helper and RhythmPatternSchema through pure edit/erase operations. An insertion replaces an event at the same start; overlap with another event or crossing the measure boundary is rejected without mutation. Preset/meter replacement asks confirmation, retains Undo and never silently truncates a pattern. Meter changes deliberately start an empty measure. Whole notes require enough space in 4/4; 6/8 does not silently change meter to accommodate one.

`PracticeTransport` is a reusable React adapter for the existing audio service. It offers Start/Pause/Resume/Stop, direct and stepped BPM, tap, volume/mute/subdivision and finish. `NumericField` preserves editable numeric text and applies only valid values; rejected cross-field settings are shown and reset to their previous valid value. Manual BPM/tap disables automatic ramp, avoiding a later bar unexpectedly pulling tempo back down to its target. Ramp settings are explicit and saved per exercise; ramp changes while a recorded run exists require finishing/discarding that run.

`usePracticeAudio` reads AudioContext time and the existing engine's played position. Its requestAnimationFrame observer only updates the display/accounting; it never schedules sound. Pause retains the last played position and pending beat fraction. Active seconds exclude suspended time; completed bars count as repetitions. Stop resets the musical cursor but retains the current reflection counters until saved or explicitly discarded. Pattern, instrument and meter edits are locked for an unfinished run; tempo and sound controls remain available. No elapsed time, target BPM or bar count automatically grants mastery.

`PracticeSessionDialog` reuses the shared native Dialog. It records a stable UUID, instrument, reported BPM, repetitions, active duration, rating, notes and explicit result. Beheerst requires its confirmation checkbox and applies to the saved configuration only. Form fields and dismissal are disabled while saving. Unsaved reflection dismissal asks confirmation; reload protection also covers edited reflection text. One in-flight save and a retained UUID prevent double-click duplicates. If a response is lost after a successful POST, the client reads that same owner-scoped UUID before deciding whether a retry is needed. Settings/snapshot are persisted before recording the session. Failed writes retain the dialog input.

## Persistence and API reuse

All catalog, settings, sessions, journal, aggregate progress and mastery continue using `/api/v1/practice`. Optional `configuration.transport` stores validated subdivision, volume, mute and ramp settings in the existing JSON configuration and immutable session snapshot. The audio engine consumes the same schema; no second validation contract is created. Catalog documents and versions are unchanged. Default playback options normalize to the legacy configuration identity, preserving earlier settings/mastery keys. Non-default transport settings conservatively form distinct persisted configurations; previous snapshots/mastery are not overwritten.

Additive migration 004 adds only practice_preferences: owner PK/FK with cascade, JSON goals (up to five), nullable FK to stable exercise identity, positive optimistic revision. GET/PUT `/api/v1/practice/preferences` use the existing trusted owner resolver and transaction helper, strict input/query validation, revision conflicts and consistent errors. No auth, public owner selector or localStorage practice data is added. LocalStorage still contains only the existing theme preference. Song documents, arrangements and their tempos are never written by Practice.

Goals and last selection are separate from musical configuration. Progress uses real stored sessions; a mastery count is labeled as exercises with a mastered configuration rather than claiming every variant is mastered. A new catalog version requires conscious review/load of its new defaults. The existing foundation retains old versions/history and enforces owner-scoped composite keys.

## Audio and lifecycle

One shared lazy Web Audio graph/context and lookahead scheduler remain authoritative. Start is a user action. 2/4, 3/4 and 4/4 use quarter BPM; 6/8 uses dotted-quarter BPM, two main pulses and twelve sixteenth positions per bar. Displayed pulse/bar follows played audio time, not the future scheduling callback. Ramp is applied once on the configured measure boundary. Hidden document pauses through the shared listener; Practice internal navigation pauses, global navigation/unmount stops, pagehide disposes. The React observer and listeners are cleaned up; no extra sound timer is created.

## Design and accessibility

The existing original logo, root dark/light theme, generated v2 tokens and shared gs-* controls/panels/notices/dialogs are reused. New screen rules are bounded to gs-practice-app. Inline CSS is only the dynamic rhythm slot count, in addition to existing musical/split properties. There are no new color literals, global screen button styles or separate Practice brand. Desktop layouts keep timeline/editor/transport together; narrow layouts use internal navigation/timeline scrolling and a normal-flow transport without overlay. Errors scroll into view without replacing the draft.

Actual landmarks, heading hierarchy, labels, visible keyboard focus, native modal focus wrapping/Escape/restore and screen-reader-friendly status text are tested. Fast visual beat updates are not continuously announced. Reduced motion comes from the existing shared states layer.
