# Stable words, syllables and LyricsLinks

Version 2 reuses stable existing token IDs for words and whitespace, grouped into explicit lines with separately preserved newline tokens. Lines keep original text order, spaces and blank lines. A word begins with one deterministic full-word syllable; this is not automatic linguistic syllabification. Manual parts must reconstruct its exact text. Whitespace has no syllables. Legacy custom text spans remain spans, not guessed word boundaries.

LyricsLink stores id/syllableId/trackId/eventIds/sustain/createdAt/updatedAt. The syllable must belong to lyrics used by this arrangement; each event must exist on the indicated track, be a note, and use this arrangement's shared measures. Duplicate event IDs and cross-song/arrangement/track references fail validation. A single syllable may link to one event, many simultaneous/sequential events or notes across bars/sections; sustain is a display hint, not a second duration source. Timing is taken only from the linked events. Word and syllable identity never derives from text equality alone.

Pure operations clone and validate before returning, so failed edits leave input unchanged. Track duplication maps all copied link event IDs to new events. Event deletion prunes only its IDs from links and removes empty links; track deletion removes only its own links. Unlinking and syllable/text deletion never deletes notes.

Free-text planning reuses the existing token LCS for unambiguous anchors. Exact unchanged text preserves all identities. Repeated words in a changed free-text span are treated conservatively: new identities and an explicit review plan instead of a semantic guess. Unique unambiguously retained words keep their syllables. The plan reports affected link snapshots, uncertain words, lost manual syllables and required confirmation; applying an edit that discards links or manual divisions without confirmation fails. Confirmed removal discards reviewed links/divisions, not tab notes. Manual syllable IDs can be retained only when explicitly supplied with identical parts. Explicit identity-based token movement preserves IDs, even for repeated text. The v1 compatibility writer refuses ambiguous linked repeated-word changes and loss of manual syllable divisions, because its editor cannot review invisible v3 links.

The plan also reports chord text anchors that would be detached and requires confirmation before doing so; their musical anchors/grips remain intact. Syllable command IDs accept the same 300-character bound as persisted syllables, including explicit retention of custom IDs.

Sprint 2F should render the review plan before calling the confirmed mutation, expose manual division and selection separately from saved musical content, and use stable IDs for bidirectional highlighting. No lyric lane, new selection UI or new screenreader behavior is shipped in this foundationsprint. LRC milliseconds and Lyricsfile words from Sprint 2D remain independent imported timing; no automatic beat/event alignment is performed.
