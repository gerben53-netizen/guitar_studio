# Multi-track foundation / schemaVersion 2

The accepted v3 prototype supplies functional intent, not production JavaScript or storage. Sprint 2E introduces no full-width editor/track dialog. Canonical current songs use the existing `studio_songs.document` JSONB and Song metadata/source/import schemas. Schema 1 remains valid and is not eagerly rewritten.

## Ownership and timeline

`multitrack.ts` defines a version-2 Song and arrangements, reusing the v1 metadata base. An arrangement owns songId/name/tempo/default meter/capo, ordered sections and shared measure IDs/meters, tracks, authoritative trackOrder, activeTrackId, legacyTrackId, chordAnchors and lyricsLinks. Every track's event refers to a measure in that one shared timeline. Measure indices/section locations are derived by `timeline`, not stored again in each track. Per-measure meter may differ; shrinking it validates all tracks before a mutation commits.

Tracks have stable IDs/arrangement ownership/name/role/visibility/collapsed/order/events and the existing InstrumentProfile. Tuning lives once at `track.instrument.tuning`; it is not copied into an additional conflicting field. The existing profile also carries capo; validation requires it to equal arrangement.capo and set-capo updates all profiles atomically. Six strings remain compulsory even for vocal_melody. Other roles: guitar_accompaniment, second_guitar, custom. Visibility/collapse never erase content. Active selection is separate from timeline/event IDs; hiding an active track retains a valid identity. Removing it selects the first remaining track; the last track cannot be removed.

All new entities use UUIDs. Legacy conversion derives stable track/line/default-syllable IDs from existing stable IDs, without randomness on reads. Shared legacy entities (words/newlines, sections, measures, events, anchors, arrangements) remain globally unambiguous; track and syllable identity are typed namespaces. Track.order mirrors the authoritative trackOrder and is validated, not an independent ordering choice. Empty/new tracks use the existing guitar profile. Duplication creates independent instrument/event/link IDs, leaves syllable targets shared with the same song lyrics, and preserves simultaneous starts/durations/tones. Destructive mutations require explicit confirmation.

Bounds: 32 tracks/arrangement, 100 sections, 200 measures/section, 200 events/track/measure, 10,000 events/track, 500 chord anchors/section, 10,000 legacy tokens/lyrics section; API body stays 2 MB. These retain safe v1 projection and bound validation cost. Larger compositions must be split or future limits reviewed. New physical positions are 0–24, above/equal capo, with pitch equal tuning[string-1]+physical fret. String 1 is high e; standard MIDI is [64,59,55,50,45,40]. Drop D remains available. Display-relative fret is physical minus capo via the existing helper. Pitch-only legacy tones are preserved without inventing fret positions; a renderer must request human fingering if needed.

## API / Sprint 2F seam

`GET /api/v1/songs/:id/multitrack` returns `{document,revision,updatedAt,storageSchemaVersion}`. A v1 source is preview-converted without a write. `PUT` accepts `{document,revision,confirmedUpgrade?,confirmedDestructive?}`; `PATCH` accepts `{revision,mutation}`. Commands cover track add/update/duplicate/delete/order/select, event put/delete, link put/delete, meter/capo, free text and syllable edits; upgrade/restore are explicit confirmed commands. Full document writes remain available rather than adding a route for every track control. GET `?view=history|backups&beforeRevision=N` returns up to 100 raw version entries and a pagination cursor; schema is never guessed from a revision number. `multitrack-client.ts` supplies transport-independent typed methods.

Every write validates the individual command and complete Song, locks the owner's current row, checks expected revision, and writes history/current state transactionally. Conflicts return 409 and currentRevision without partial mutation; other owners receive 404 on canonical routes. A request cannot nominate its owner. The prior trusted local principal remains the production boundary; no authentication was added. External preview-only import content remains forbidden.

Existing Song CRUD returns a schema-1 projection plus storageSchemaVersion. Reads never downgrade storage. Writes merge only the designated compatibility track, timeline/metadata/anchors and safe text changes into the full canonical Song, preserving hidden tracks/links/import provenance. Unsafe deletion/retiming or loss of linked/manual syllables is rejected with 409. The old editor cannot perform arbitrary new multi-track operations; use the canonical contract in Sprint 2F. Source backups/history remain available. Canonical JSON exports and duplication carry all tracks/links; imports remap every entity/reference to independent IDs. An unsafe unsaved compatibility draft can export a recovery envelope with full canonical base plus v1 draft for explicit review, rather than silently exporting only one track. No recovery envelope is silently applied.
