# LRCLIB provider

Authoritative technical reference: [LRCLIB docs.txt](https://lrclib.net/docs.txt), checked 2026-11-14. Format reference: [Lyricsfile 1.0 draft](https://github.com/tranxuanthang/lyricsfile/blob/main/SPECIFICATION.md). These are separately versioned contracts; permissive API access is not a blanket composition-content license. See [provider rights decision](song-discovery-providers.md).

Production adapter: `apps/api/src/lrclib.ts`. v2 lightweight `/api/v2/search` is primary. `q` takes precedence; otherwise track_name/artist_name/album_name are passed. Artist-only maps to free `q`, because LRCLIB requires q or track_name (broader artist search, not exact artist-only filtering). At most 20 results and no pagination. v1 `/api/search` fallback only on unavailable/incompatible beta responses (404/405/upstream 5xx/timeout/invalid JSON/schema); never on an empty result, 400, 401 or 429. v1 bodies are normalized to metadata and immediately discarded; not cached/logged/persisted. Selected `/api/get/{id}` retrieves full record only after selection; numeric validated IDs and redirect rejection keep host/path fixed. Optional signature `/api/get` is not implemented because result IDs suffice.

Result metadata includes ID, title, artist, album, duration, instrumental and availability flags. Detail returns plain lyrics, separate millisecond LRC/Lyricsfile synchronization, raw synchronization sources, warnings and preview-only source policy. Instrumental/missing lyrics are explicit states, not fabricated errors/content. Unsupported YAML is preserved for temporary source inspection with a warning, never executed or persisted.

Identification: `GuitarStudio/0.2.0 (https://github.com/gerben53-netizen/guitar_studio)` User-Agent. Optional `LRCLIB_APP_ID`/`LRCLIB_API_KEY` become server headers; no registration is required and no default fake key is sent. Configure through the server environment, never React/VITE variables. No raw provider body or credentials appear in application logs.

Shared provider queue serializes requests, accepts at most eight queued/in-flight operations, enforces 350 ms minimum spacing, 7-second external timeout, bounded one retry for 429/500/503 and exponential default delay plus 0–30% jitter. Retry-After accepts seconds or HTTP date and is a lower bound. Long cooldown (>5 seconds) returns controlled status/Retry-After rather than holding the caller; future/queued operations respect the same cooldown. API also limits IP requests. No automatic per-keystroke requests: the UI submits explicitly, aborts on changed input/new search/unmount and ignores obsolete responses. Rate limits listed in LRCLIB docs are indicative; no fixed capacity guarantee is assumed. Queue/rate state is per process; production scale would need shared state.

400/401/404/429/500/503, network failures, timeout, non-JSON errors, invalid JSON, changed schemas and unexpected fields are covered by deterministic tests. Upstream responses are streamed with a 2 MB bound; no redirects. Content-bearing field sizes and normalized shape are separately validated. Search results never carry v1 lyric payloads through to the client.

LRC preserves original source, multiple/repeated timestamps, minutes/seconds/fractions, blank/unmarked/invalid lines (null timing + warning), and no inferred end. Lyricsfile YAML uses the safe `yaml` core schema, one document, no duplicate keys/custom tags/anchors/aliases, bounded source/depth/arrays and strict version/metadata/line/word structure. Timing must be nonnegative integer milliseconds and end >= start; word text must rebuild its line. Unknown schemas are not silently reinterpreted. Offset stays in original source with a warning because the draft semantics are unresolved. Word availability flag is cross-checked against validated content. Neither seconds nor milliseconds are transformed into bars/beats/events.

Limited live smoke (2026-11-14T18:19:57Z): v2 structured search for the official docs example returned two actual records (limit 2), selected ID 7621759 returned 46 plain-text lines and line synchronization, zero parse warnings, preview-only policy. Only metadata/counts were retained; no full external lyrics in evidence/database. CI uses deterministic network mocks and does not depend on LRCLIB uptime. Live availability is a point-in-time observation, not a service-level promise.

Permanent external lyrics import/export/republication is disabled. Metadata/temporary preview works. User-created/independently rights-confirmed manual input remains available via the ordinary wizard; this does not turn copied third-party text into licensed content. Enabling future provider imports requires a documented grant, server-enforced per-record policy and corresponding provenance/tests, not a client checkbox alone.
